# Canon Ledger — met concepts and declared gaps

> **Kind: REPORT.** This register records what the work MET, in the session it was met.
> It declares nothing binding on its own; a row becomes law only by restatement in an ADR.
> It grows in two directions: **upward** (a concept rising to its home) and **inward**
> (a question the design could not answer, declared *before* it is improvised around).
> A register whose rows never leave it has become a graveyard.

## Gaps — questions the design could not answer

Declared at the moment they were met. An improvised answer is allowed; an improvised answer
that leaves no trace is not.

| Gap | Met | Status |

| **Approval is a moment, not an identity.** `--approve <who>` writes `signed_by` verbatim: the kit records the string it was handed and cannot tell an owner from an automation from a typo. | **A host may change its mind, and nothing uninstalls.** Selection is expressible only *before* the first answer; afterwards the answers file is the truth and `--enable/--disable` are refused against it. | **`never_disabled` is a declaration nobody reads.** `MANIFEST.json` marks `governance` as never disabled; no interpreter consults the flag, because there is no selection mechanism for it to constrain — a capability is enabled iff its requirements are met. Either a selection mechanism arrives and reads it, or the field goes. | 2026-09-09, slice B | **CLOSED**, slice C — the field LIVES and is read by `resolver.select`. | **Only the running process can say whether a run is alive, and a record cannot carry that.** A run may not judge its own liveness, so the reading of a record carries `in_flight` — true only of the run doing the reading. It is honest inside one process and unavailable to every reader outside it: a second process, a later session, a CI log or a human opening the file cannot tell a live run from a dead one, and every record of a currently-running kit reads to them exactly like a corpse. The kit has no port for process liveness (a pid, a lock, a lease, a heartbeat), and inventing one was out of slice. | **A gate cannot state the size of the set it was applied to.** `check` prints `PASS  FF-RUN-RECEIPT`, and it prints exactly that whether it read fifty records or none. On the SURFACE the empty scan and the thorough one are indistinguishable, which is precisely the failure mode the rule names. Refusing an empty collection was rejected: a host that cleared its ephemeral plane legitimately has none. Candidate cures, none chosen: a gate reports the size of its subject beside its verdict; or a gate declares the minimum set it must have been pointed at. | 2026-09-10, slice G | OPEN — the rule is measured in tests and unstated on the surface |

## Rule earned here, stated without the vocabulary of its case

> **Half-built state is not partial success; it is unverified state.** A run that dies mid-way
> leaves artifacts that read exactly like finished ones. Six defects sat in the half of slice A
> written by a mind that never got to execute anything — including a template in the wrong
> language and a declaration class nobody validated. The cure is not vigilance: it is that
> nothing counts as built until it has been RUN, and that the first green is never trusted
> without an adversarial probe designed to make it fail.

> **A promise two mechanisms keep separately is not a promise; it is a coincidence with a good
> record.** A preview that recomputes what the real run will compute is correct exactly until
> someone edits one of them, and the failure is silent because both halves remain internally
> right. The cure is never diligence and never a review checklist — it is that there is only ONE
> decision, made once, printed by one caller and consumed by the other. Slice C's probe is the
> proof and the method: give the second half permission to decide for itself, and watch which
> assertions go red. If none do, the guarantee was never being measured.

> **A layer of judgement added above another must not answer first — and this is the second time
> it has happened.** Slice B: composition refused before the measurement it followed from could
> report. Slice C: looking up the answers file refused before the composition that explained why
> the declaration was missing. Same shape, different layer, so it is no longer an observation —
> it is a rule we are already paying for twice. A lookup that a later step needs is resolved
> LATE, where its absence is a real answer, never early where it merely happens to be convenient.

> **A projection is a reading, and a reading states the moment it was taken.** Whenever one
> artefact is derived from another that a human may author, there is a window in which the
> derived one is honestly obsolete — and a checker that reports this as a generic mismatch is
> naming a symptom where a state exists. The system already has the vocabulary for this: unbound,
> empty, stale, partial are DECLARED states. `stale` is the one it declared everywhere except
> about itself. Met twice, in two unrelated capabilities, which is how a rule announces that it
> was never about either of them.

> **An attribution that cannot fail does not measure — it certifies.** The dangerous half of a
> passing gate is never the assertion; it is the SET the assertion was applied to. A harvest that
> yielded nothing, a seed nobody could judge, two hosts that happened to resemble each other —
> each passes gloriously while measuring an empty set, and reads exactly like a scan that looked
> and found nothing. So a sensor proves TWO things before it is believed: that it can see a
> crossing, and that it was pointed at something.

> **A width is an assumption, and an assumption at a boundary is a lie waiting for a longer
> name — and this is the second time it has happened.** The kit's plan report reserved a fixed
> number of characters for a declared name. The day a name was one character longer, two columns
> ran together, the row still read as a perfectly plausible row, and every reader — human and
> machine — parsed one field where there had been two. Nothing raised, nothing warned; three
> assertions simply began comparing a set that had quietly lost four of its members. It is the
> same shape as the line ending that was normalised on somebody else's machine: a boundary
> believed rather than measured, staying correct exactly as long as nobody stood at the edge of
> it. Seen twice, so it is no longer an observation. Every dimension of a rendered surface — a
> width, a separator, an encoding, a limit — is DERIVED FROM THE DATA it must carry, or it is a
> guess that will one day be wrong silently.

> **A record written only at the end proves nothing about a run that never reaches the end.** The
> artifacts of a run that died read exactly like the artifacts of a run that finished, and no
> amount of looking at them will separate the two — the difference is not in what was produced, it
> is in whether anything was ever CONCLUDED, and only the run itself could have said that, and
> only before it stopped being able to. So the trace is opened before the work and closed after
> it, and the close is the part that is allowed to be skipped. Everything that reports on a
> process from outside it inherits this: a status computed at the end is a status that exists only
> for the runs that did not need it. This slice was designed inside its own subject — the previous
> attempt at it was killed mid-way and left five finished-looking files that had never been run —
> which is the only reason the rule is stated here as an identity rather than as a nice idea.

> **A surface that says nothing when nothing was declared is indistinguishable from one saying
> everything is fine.** The two states are opposite and the rendering is identical, so the reader
> supplies the difference from their own optimism — and supplies it in exactly the direction that
> stops them looking. The cure is not a warning banner: it is that the ABSENCE is given a name, a
> record and a count, so it occupies space on the surface proportional to what is missing. Every
> zero in this system is a declared zero, or it is a lie waiting to be believed.

> **A refusal must stop the WHOLE operation, never the path.** Skipping the one thing that could
> not be reconciled and applying the rest leaves a tree in a state no version describes — neither
> the old one nor the new one, and nothing on disk says which. The partial application is worse
> than the failure it was trying to survive, because the failure was legible. Every mechanism that
> can refuse must refuse entirely, in the plan, before a byte moves.
