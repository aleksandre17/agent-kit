# Canon Ledger — met concepts and declared gaps

> **Kind: REPORT.** This register records what the work MET, in the session it was met.
> It declares nothing binding on its own; a row becomes law only by restatement in an ADR.
> It grows in two directions: **upward** (a concept rising to its home) and **inward**
> (a question the design could not answer, declared *before* it is improvised around).
> A register whose rows never leave it has become a graveyard.

## Gaps — questions the design could not answer

Declared at the moment they were met. An improvised answer is allowed; an improvised answer
that leaves no trace is not.

| Gap | Met | Status |
|---|---|---|
| **An uninstalled host has no declared state.** The design has vocabulary for an *unavailable capability* and none for *"the kit is not installed here"* — only an absence. `init` exits non-zero and names the unmet fact, so the surface does not lie; but `check` afterwards reports the missing `project.json` rather than the unmet requirement that caused it, so the *second* reading names a symptom where the first named the cause. | 2026-09-09, slice A, `test_10` | OPEN |
| **`project.schema.json` requires `capabilities` with `minItems: 1`**, structurally forbidding a host that legitimately enables none. The schema encodes an optimism the mechanism does not require. Changing a BINDING schema was out of slice. | 2026-09-09, slice A | OPEN — **reframed, slice C.** With `never_disabled` now read, a set with no capabilities is unreachable through the selection mechanism, so `minItems: 1` no longer encodes optimism the mechanism does not require: it encodes something the mechanism now enforces. Two homes for one truth, and the schema's is the one nobody can date. Still open, and now for the sharper reason. |
| **When has an interpreter's vocabulary become a privileged name?** The install modes (`seed` · `reading` · `declaration`) carry no proper noun and are generic — yet they are the closest thing to policy inside the interpreter, and Cardinal IV offers no test for the boundary. The proper-noun grep passes; the question it answers is narrower than the question that matters. | 2026-09-09, slice A | OPEN — **narrowed, slice F.** Two of its three cases now have a mechanical answer: a machine may name what its SCHEMAS declare and what it PROVIDES as a registry key; anything an instance invented is refused. The residue is where the row first pointed — the install modes qualify as *provided* because `INSTALL_MODES` binds them to behaviour. What is now known: provision is a property of the mapping, so a registry is also the one place a domain word could be laundered in. |
| **The kit does not ship itself.** `.agents/kit/` receives only what a capability declares, so `__pycache__` appeared *inside the payload* the first time the kit ran — the unclassed-state condition the layout proposal diagnoses, reproduced by the kit against itself. The declared cure is manifest-enumerated shipping via `kit.lock.json`, out of slice A. Fenced with `.gitignore` and named here rather than smuggled in early. | 2026-09-09, slice A | OPEN — cure named, deferred |
| **Schemas cannot compose.** `validation.py` implements no `$ref`, so no schema may reference another. Adequate for every schema in the kit today; it will bite at `role.schema.json`, where a role composes an archetype. | 2026-09-09, slice A | OPEN — dated trigger |
| **A capability may install outside every declared plane, and nothing classes it.** `knowledge` installs into `docs/`, which is MADR's canonical home and correctly NOT `.agents/`. Its files get a class from their exact target declarations, but `FF-KIT-CLASS` walks `.agents` only, so under `docs/` there is no totality: a stray file there resolves to no class and no gate says so. Extending class-totality to `docs/` was refused deliberately — it would forbid the host from keeping any document the kit did not declare, which is not the kit's business. The real question the design cannot answer: **what is the class of a path the framework writes into but does not own?** | 2026-09-09, slice B | OPEN |
| **"Append-only, immutable once accepted" is doctrine with no gate.** `docs/decisions/` declares, and an accepted ADR is supposed to be superseded rather than edited. Nothing measures that: the kit sees one filesystem state and has no history, so an edited decision is indistinguishable from one that always said this. Any cure needs a recorded prior reading (content digests in a lockfile, or git history read through a port) — both deferred with `kit.lock.json`. Until then the rule binds humans and no machine, and the ledger says so rather than the ADR implying otherwise. | 2026-09-09, slice B | OPEN — cure named, deferred |
| **Approval is a moment, not an identity.** `--approve <who>` writes `signed_by` verbatim: the kit records the string it was handed and cannot tell an owner from an automation from a typo. The acceptance suite signs as `acceptance-suite` and the answers file reads exactly as an owner's would. So P3 proves that *someone deliberately passed the door*, which is a real guarantee, and it does NOT prove *who* — a door that cannot recognise a face records attendance, not consent. Any cure crosses a boundary the kit has no port for (a VCS identity, a signature, a review). Named rather than implied by the field's name. | 2026-09-09, slice C | OPEN |
| **A host may change its mind, and nothing uninstalls.** Selection is expressible only *before* the first answer; afterwards the answers file is the truth and `--enable/--disable` are refused against it. Editing that file to drop a capability therefore removes it from the enabled set while every file it already wrote stays on disk, owned by a capability the host no longer runs. `FF-KIT-CLASS` does not catch them: class declarations come from the whole MANIFEST, not from the enabled set, so an orphan still resolves to exactly one class and reads as legitimate. The kit can add a capability by choice and cannot subtract one. | 2026-09-09, slice C, met while writing `_chosen` | OPEN — needs `upgrade`, deferred |
| **`never_disabled` is a declaration nobody reads.** `MANIFEST.json` marks `governance` as never disabled; no interpreter consults the flag, because there is no selection mechanism for it to constrain — a capability is enabled iff its requirements are met. The flag anticipates a host CHOOSING its set, which does not exist yet. A declared field with no projection is exactly the drift Cardinal III warns about, only pre-emptive: it reads as enforced. Either a selection mechanism arrives and reads it, or the field goes. | 2026-09-09, slice B | **CLOSED**, slice C — the field LIVES and is read by `resolver.select`. Ruled on rather than kept: `governance` owns the host's reading, its answers file and the gates that class every path, so a set without it has no way to describe itself. It stays on the MANIFEST ENTRY, not in the capability: a capability declaring itself indispensable would be granting itself authority, and which of its own parts a kit cannot stand without is a statement the KIT makes. Evidence is a DIFFERENCE, not a message — `test_32` runs one command against two kits differing only in that field and gets two different refusals, so the flag is provably what fires. |
| **Composition is proved for a set the KIT declares, never for one a HOST chose.** Every composition case in slice B is built by patching a fixture manifest, because a host cannot yet enable or disable anything. `requires`, `provides`, `conflicts`, ordering and shadowing are therefore proved as properties of *declarations*, not of *host choice* — and the difference is where the interesting failures live (a host disabling a capability something else needs). | 2026-09-09, slice B | **CLOSED**, slice C — the host chooses, and the choice has one home: `--enable/--disable` author the answers file before it exists, and afterwards the answers file IS the set and a contradicting flag is refused (`test_34`). `test_30` asserts a subset BOTH ways — the chosen capability's paths present, every path of the excluded one absent, its whole plane gone. `test_31` reaches the case slice B could not: a host that drops a capability another REQUIRES is refused, told which CHOICE caused it (`which this host chose to disable`, distinct from the measured `which this host cannot support`), and the host is asserted byte-empty afterwards. |
| **A projection over a host-authored binding is stale the instant the host authors**, so `check` is red between authoring and `render`, and the doctrine says whose duty it is to close that window nowhere. Met in delivery, met AGAIN in hygiene, which had to run `render` first in two tests to work around it. Candidate resolutions, none chosen: (a) `check` declares projection-staleness as its own named state instead of a generic byte-diff failure; (b) a `stale` disposition reporting the moment of the last render; (c) `check` refuses to judge a projection whose inputs are newer than it. | 2026-09-09, slices D and E | OPEN — **seen twice, so it is no longer an observation.** The rule it earned is stated below; the mechanism that would enforce it is still unbuilt. |
| **May a residence rule ever be enforced by REMOVAL under human sign-off?** The `move`-style door exists for cards and not for files. `hygiene` answers "never" locally — a capability's choice standing in for a doctrine that is silent, which is exactly the shape Cardinal VI says to declare rather than improvise past. | 2026-09-09, slice E | OPEN |
| **T1's quiet half measures COUPLING, not prose — and that scope was never declared.** The rule flags a consumed term only inside a quoted string literal, so `doors.py` spells a delivery transition (`shaped -> bet`) in its docstring and passes. Defensible — a docstring example does not couple an interpreter to an instance — but it is a scope the sensor keeps and does not state, and the reader cannot tell a deliberate limit from a miss. Found by the orchestrator's own verification, not by the slice. | 2026-09-10, slice F, verifying | OPEN — the limit is honest; its silence is not |
| **A framework cannot be made to leak from a declaration alone.** T3's calibration must PRESENT its specimen to the sensor rather than produce it from a rigged kit: the CLI is always the real kit's, a fixture kit patches only payloads and declarations, and no payload expression can emit a host-varying value that is not already declared. A good property of the design and a hole in the method — T3 proves the sensor's edge honestly and has never seen a REAL crossing. A cure needs a fixture kit whose interpreters are the ones that run. | 2026-09-10, slice F | OPEN |
| **A host-authored binding has no ancestor.** T3's ancestor set — the measured reading, the host's answer, the declaration of a capability it chose — is total only for a surface read IMMEDIATELY after install. The moment a host authors into a binding, its content is a legitimate cause the attribution would name as a leak. Unreachable today; real the first time T3 runs against a lived-in host. | 2026-09-10, slice F | OPEN |
| **Only the running process can say whether a run is alive, and a record cannot carry that.** A run may not judge its own liveness, so the reading of a record carries `in_flight` — true only of the run doing the reading. It is honest inside one process and unavailable to every reader outside it: a second process, a later session, a CI log or a human opening the file cannot tell a live run from a dead one, and every record of a currently-running kit reads to them exactly like a corpse. The kit has no port for process liveness (a pid, a lock, a lease, a heartbeat), and inventing one was out of slice. The mechanism is therefore SOUND for the reader it was built for and SILENT for every other, which is the shape the doctrine says to declare rather than improvise past. | 2026-09-10, slice G, met while designing the gate | OPEN — cure needs a liveness port |
| **A gate cannot state the size of the set it was applied to.** `check` prints `PASS  FF-RUN-RECEIPT`, and it prints exactly that whether it read fifty records or none. The ledger's own rule — *an attribution that cannot fail does not measure, it certifies* — is honoured only in the acceptance suite, which requires the collection to be non-empty before believing the green. On the SURFACE the empty scan and the thorough one are indistinguishable, which is precisely the failure mode the rule names. Refusing an empty collection was rejected: a host that cleared its ephemeral plane legitimately has none. Candidate cures, none chosen: a gate reports the size of its subject beside its verdict; or a gate declares the minimum set it must have been pointed at. | 2026-09-10, slice G | OPEN — the rule is measured in tests and unstated on the surface |
| **`observe → enforce` is still not a number.** ADR-001's open gap, met head-on. This slice refused to hold a tolerance field nobody had filled in — an unread threshold reads as *enforced*, which would be worse than none — and instead states the absence on the projection: there is no observe-then-enforce period, the first crossing is a finding. That makes the SURFACE honest and closes nothing: P9 remains a description, because the number it needs has still never been declared anywhere. | 2026-09-10, slice G | OPEN — **narrowed:** the absence is now declared on a surface instead of implied by silence |
| **Nobody judges the judge.** `llm-rubric` and `llm-pairwise` are themselves declarations, and the one measurement that would make a judge's verdicts evidence rather than testimony — its agreement with a sample a human trusts — exists nowhere in this doctrine. The slice REFUSED to build it: a meta-evaluation needs a held-out sample, and a sample is domain. So a judgement is trusted exactly as far as the host trusts the judge named on it, and that limit is DECLARED on the projection rather than implied. A quality receipt sits in the same trust hole a vendored hook sat in — with the difference that the hole is now on a surface. | 2026-09-10, slice H | OPEN — declared, deliberately unfilled |
| **The framework can declare a verdict and cannot declare a SCALE.** `UNJUDGED · PASS · FAIL · INCONCLUSIVE` is shippable because it is a grammar of outcome. A NUMBER is not: how much better one answer is than another is a statement only a domain can make, so a host needing 1–5 or a weighted rubric has nowhere to declare it. Stated rather than half-built — an ordinal a framework picked would be a domain opinion wearing a type. | 2026-09-10, slice H | OPEN — cure needs a host-declared scale |
| **The zero measure is stated by a verb and enforced by no gate.** `check` cannot fail a host that declares fifty cases and judges none, because failing it needs a coverage threshold, and the number at which observing becomes enforcing has still never been declared. The measure is honest on every surface that PRINTS it and invisible to the one that GATES. This is slice G's gap reaching where it hurts most: the set whose SIZE is the finding. | 2026-09-10, slice H | OPEN — same cure as the slice-G row |
| **An assertion over a DEFAULT SET is a second home for the manifest.** `test_24` asserts a literal install order; every new capability turns it red for a reason unrelated to what it measures. Seen at slice G and again at slice H, so it is no longer an observation. The order it means to measure — dependencies first, ties by id — is DERIVABLE from the declarations it already reads. The assertion is right; its subject is a copy. | 2026-09-10, slices G and H | **CLOSED**, slice L6 — paid before the slice that would have reddened it a third time. `test_24` now DERIVES the sequence it expects from the same declarations the run reads: `dependency_levels` transcribes the rule in the test's own words (capabilities ready at once form a LEVEL; inside a level, by id), and `expected_install_order` composes it with the phase rule (every install of the set precedes every projection of the set). Nothing imports `resolver` — the rule is written twice in two languages, so a disagreement is a finding rather than a tautology. The derivation made the LEVEL explicit, which a literal list could only imply: `observability` precedes `hygiene` not by a tie-break but because they sit on different levels. Four guards stop a derived expectation from being vacuous — non-trivial length, the same path SET as the run, every capability contributing at least one path, and no requirer reached before its provider, asserted over the WALKED order. Proved with two mutations: reversing the tie-break, and dropping the dependency test — each turns it RED. |
| **Schemas cannot compose — the dated trigger arrived early.** The judgement dispositions needed exactly the row shape `observation.schema.json` already declares, and with no `$ref` the choice was to DUPLICATE the shape or WIDEN the existing schema to cover a second kind of record. Widening was taken and stated in the schema's own prose: the right answer under the constraint, the wrong shape without it. One schema now means two things because it cannot mean one thing twice. | 2026-09-10, slice H | OPEN — the recorded `$ref` gap, now paid for once |
| **Schemas cannot compose — the dated trigger arrived, and the bill was refused this time.** The row of 2026-09-09 named `role.schema.json` as where it would bite, and slice L6 is that slice. Widening was NOT taken again. Two schemas are declared instead — `archetype` and `overlay` — each complete, standalone and meaning exactly one thing, and the COMPOSITION of them is validated by an interpreter rather than by a schema. This is not a workaround dressed up: the one property that mattered is the one `additionalProperties: false` gives for free, namely that an overlay is CLOSED to the archetype's vocabulary and so cannot hold a second body. A `$ref` would have made the two documents share a shape; what this design needs is the opposite — that they provably do NOT. What is genuinely lost is stated rather than implied: no schema can express *the merge of these two must be complete*, so "an instance never overrides" and "a composed row is total" live in `composition.py` and are proved by acceptance tests, not by validation. Read against slice H: widening bought composition at the cost of meaning; declaring twice buys meaning at the cost of a rule the validator cannot see. | 2026-09-10, slice L6 | **the trigger fired; the gap is unchanged and the bill was paid differently** |
| **A plan cannot state the write set of a projection whose inputs do not exist yet.** A projection that writes one file per record has a target set that is a function of a binding, not of a declaration. Planning an install on a fresh host therefore reaches for content that install has not created. The first draft named the collection root so the operator would see *something*, and that was a LIE the apply refused to keep — the path is never written — and `test_36` caught it within the hour. The plan now contributes NOTHING there, which is honest and, in the only case that reaches it, also the correct number: a host with no records gets no files. It stays a gap because the honesty is accidental. The moment a plural projection's records can pre-exist the plan, an empty plan will under-promise and the apply will write files nobody was shown. The cure needs a disposition the vocabulary does not have — a planned effect whose extent is *not yet knowable* — and adding one touches every reader of `DISPOSITIONS`. | 2026-09-10, slice L6 | OPEN — cure named, deferred |
| **A composed row's shape comes from a schema, and only some readings have one.** An optional field must reach a surface as a field that is empty, never as a name that does not exist, or nothing downstream can tell a typo from an honest blank. The union of what today's records happen to carry is not that shape — an optional field nobody has used yet is missing from it exactly when a host first needs the surface to say so — so the shape is read from the SCHEMA that judged the reading, and `Reading` now carries the schema it was validated by. That is total only where an install declared `validates`. A readable with no schema composes rows whose shape is a reading of today's content, and the renderer's honest-blank rule silently weakens there. Nothing in the kit is in that state today; nothing forbids it either. | 2026-09-10, slice L6, met while the renderer refused an optional field | OPEN |
| **The archetype/overlay line is enforced by two disjoint schemas, and nothing measures that they STAY disjoint.** The whole structural guarantee — a host cannot write a second body — rests on the overlay schema declaring none of the archetype's property names. `test_93` asserts it, so the kit's own pair is measured. But a capability that declared a `composes` block over two schemas that happened to share a key would get precedence-free refusal at merge time (correct) and no warning at all until a host hit it. The invariant belongs to the `composes` declaration and is proved only for one instance of it. | 2026-09-10, slice L6 | OPEN — a fitness function over the declaration, not over the kit's one use of it |
| **A HOST IS ASSUMED TO BE A WHOLE REPOSITORY, AND NOBODY EVER DECLARED THAT.** Every verb takes one `--root` and installs one surface, so a repository whose parts are genuinely different subjects — a monorepo where `packages/core` has its own law, its own roles and its own measure — has no way to say so. The blueprint DETECTS the fact (`stack.node.workspaces`, `pnpm-workspace.yaml`) and seeds a per-module law document, so the shape was seen; the MECHANISM was never designed. Nothing refuses a nested install today, which is worse than a refusal: two hosts would quietly share one answers file and one reading, and each would be internally right. The open question is not "can we run it twice" but *what does a nested host INHERIT and what may it CONTRADICT* — and that is the same grammar question as archetype ⊕ overlay, one level up. | 2026-09-10, raised by the owner asking whether the framework initialises a project's inner parts; the orchestrator checked and found no declared answer | OPEN — **belongs beside `adoption`: both are the kit meeting a structure it did not create** |
| **Consent is recorded against a PATH and a VERSION, never against a CHANGE** (`GAP-DOCTRINE-SEMANTICS`). Upgrade's door writes a name, a moment and the superseded digest onto the estate row, so a host that has AMENDED its doctrine is protected — it lands in `diverged-kept` or `conflicted` and must answer. A host that has not amended anything is consenting to bytes it has not read. Closing this needs doctrine to carry its own versioned identity, so that what changed can be stated rather than merely which file did. | 2026-09-10, slice `upgrade`, ADR-002 | OPEN — declared, deliberately deferred |

## Canon met — status per Law 13

| Concept | Status | Note |
|---|---|---|
| **Mustache (logic-less templating)** | *adopted as a NAMED SUBSET* | Sections, inverted sections, dotted paths, standalone-line stripping. Refuses partials, lambdas, `{{{ }}}`. **Deviation named:** a missing key RAISES rather than rendering empty — the projection plane may not lie (Cardinal V). This refusal is what exposed a `.mustache` file that was actually Handlebars. |
| **Ports & Adapters** | *adopted whole* | `Manifest · Workspace · Probe · Clock` at the verb boundary. |
| **Capability-declared write scope** (least privilege / object-capability) | *newly met, adopted* | A capability's `installs` list is simultaneously its manifest AND its permission set. A second home for that truth is impossible because it is one list. This is our addition beyond the ports pattern. |
| **JSON Schema** | *partial, missing part NAMED* | No `$ref`, no combinators. Unsupported keywords are refused loudly rather than ignored — a validator that silently skips what it cannot check is worse than none. |
| **Debian conffile / copier answers-file** (create-once host truth) | *adopted in part* | Realised as the `seed` / `reading` / `declaration` install modes. The lockfile half is proposed, not built. |
| **Git end-of-line normalisation as a measured boundary** | *adopted* | The kit asserts `render` is byte-reproducible; the first commit emitted 26 LF→CRLF rewrites. Both git and the renderer behaved correctly and the guarantee was false outside this machine — while still reading as true from inside, because the local test passed. `.gitattributes` pins LF everywhere. **Cardinal VII, found in this repository's own first commit.** |
| **FF-KIT-SECOND-HOST** | *built and GREEN* | The framework's central claim — that it is portable — is now measured rather than asserted. Eleven assertions against a scratch repository it has never met. |
| **Diátaxis × MADR × the Kind Law** | *adopted, crossed* | Diátaxis says what a document is FOR; MADR says how a decision is RECORDED (canonical `docs/decisions/`, adopted rather than invented); the Kind Law says what a LOCATION may grant. The cross is the capability: authority is a property of location, never of prose, so the gate reads a name and a path and never a word of content. |
| **Dependency resolution (topological, total order)** | *adopted whole* | Kahn with a sorted frontier: dependencies first, ties by id, result independent of declaration order — asserted by reversing the manifest and demanding the same emitted order. |
| **Provision over identity (substitutability)** | *newly met, adopted* | A `requires` of kind `capability` matches what capabilities **provide**, never their ids; a capability's own id is not an implicit provision, because a name is not a contract. Measured both ways: renaming the provision breaks the requirer, renaming it on both sides installs cleanly. |
| **Shadowed path = defect, not precedence** | *newly met, adopted* | Two capabilities installing to one path is refused before the first byte, naming both owners. There is no last-writer-wins and there must never be one: the loser's declaration would go on reading as true while the bytes came from elsewhere — both locally correct (Cardinal III). |
| **Measurement is reported before composition refuses** | *earned in slice B* | Adding a capability-level requirement silently swallowed slice A's honest `unavailable governance` report: the refusal fired first and named the consequence. The cure was structural, not a weakened assertion — `classify` (measures, never refuses) is separated from `compose` (refuses, never measures), and the caller reports between them. **The general rule: when a new layer of judgement is added above an existing one, the existing one's report must still reach the surface first — a cause that arrives after its consequence is not a report, it is a correction nobody asked for.** |

| **Terraform plan/apply** | *newly met, adopted whole* | `--plan` is a FLAG on every verb that declares `MUTATES`, never a sixth verb, and it is not a preview: the verb DECIDES once and the plan and the apply are the same value, entry by entry. Each install mode has two halves — FORESEE (what would happen) and APPLY (which is handed the answer and decides nothing). Measured by comparing a plan run's rows against the apply run's lines (`test_36`, `test_37`), and by a mutation probe: making the apply decide for itself turns two slice-A assertions red. |
| **Copier's answers file** | *promoted from "in part" to adopted* | Slice B had the create-once install modes; the half that was missing was the ANSWER. `project.json` is now what the HOST chose, authored by `--enable/--disable` exactly once and thereafter the source of truth, with a flag that contradicts it refused rather than obeyed. |
| **The unanswered case as a declared state** | *newly met, adopted* | An install whose approval never came is `status: draft`, DATED, on disk, and every verb declaring `REQUIRES_APPROVED_HOST` refuses while it stands, naming the date. It carries its own exit code (3), because a stalled install is not a broken one and an operator who cannot tell them apart will either ignore real defects or re-run a refusal forever. Cardinal V at the one door in the design. |
| **Verb-declared preconditions** | *newly met, adopted* | `MUTATES` and `REQUIRES_APPROVED_HOST` are declared BY each verb and read generically by the CLI, which still knows no verb's name. Asking a non-mutating verb for a plan is refused rather than answered with an empty one — an empty plan reads as "nothing to do", which is a different statement from "this verb never writes". |
| **Residence / the calibrated sensor** | *adopted whole* | Declared by `kit/capabilities/hygiene/residence.json` and read by `gates/hygiene.py`. A genre of document that has no home is a DECLARED row — pattern, reason, destination — and each row carries its own calibration: one path it MUST match and one lookalike it MUST NOT. If any rule fails its calibration the tree is NOT SCANNED AT ALL and the uncalibrated rule is the finding. A sensor that has not proved what it sees may not report on the tree, still less act on it. |
| **Sensor and actuator, separated** | *adopted whole* | `hygiene` NAMES residents and cannot remove one: no write, and no port through which a write could be reached. The slice's label was wider than its honest content, and the narrower thing was built. |
| **Fitness function calibrated by specimen** | *adopted whole, second capability* | Slice E earned it for residence; slice F carries it to a sensor of another shape, where the specimen is a whole two-host measurement rather than a path. A rule declares one specimen it must FLAG and one it must ADMIT, in whatever form its kind reads; an uncalibrated rule stops the scan and is itself the finding. |
| **The measured boundary (T1 · T2 · T3)** | *adopted whole* | Declared as DATA in `kit/fitness/boundary.json`; the test module knows none of the rules' names, so a new measurement is a row. T1 found a real defect on its first run (`Governed.__slots__` carried one capability's collection name); T2 found the sharper one — the delivery policy seed shipped a host's answers (`wip_limit`, `max_age_days`) in the one file no upgrade revisits. |
| **OpenTelemetry span vocabulary** | *adopted as a NAMED SUBSET; the tooling deliberately NOT built* | A run's record carries a **name**, a **status** of `UNSET`/`OK`/`ERROR`, and a **status message**, in OpenTelemetry's words, because a receipt that invents its own words for a thing the field already named is a second home for a vocabulary. **We wrap, we do not replace:** no collector, no exporter, no SDK — a record is a JSON file in the ephemeral plane. **Two deviations are stated in the schema rather than left to be discovered:** the identity is `id`, because that is what a member of a collection is identified by everywhere in this kit and a record carrying both `id` and `trace_id` would have two homes for one value; and moments are ISO-8601 from the clock port, because a field named for nanoseconds holding an ISO string is a name that is not its referent. |
| **Write-ahead / crash-only recording** (state it before you can lose it) | *adopted whole* | The record is written the moment a run BEGINS, holding `UNSET`, and rewritten exactly once at the close — which lives in a `finally`, while the open does not. A killed process therefore leaves its record open forever, and that is the mechanism succeeding. Measured two ways rather than asserted: a fixture kit declares a disposition over `in_flight` and so watches its own live record from inside the run (`test_71`), and a real process is killed where it stands (`test_72`, which asserts both that a record appeared *while the run was alive* and that the run had *not already finished* — either omission would have left the test agreeing instead of measuring). |
| **Sensor and actuator, separated** | *adopted whole, second capability* | `observability` NAMES a run whose record says something is wrong and removes nothing. Sharper here than in hygiene: a run's record is EVIDENCE, and evidence is not swept up by the thing being questioned. |
| **The exclusion that is declared instead of hidden** | *newly met, adopted* | A sensor that must skip something states the skip as a FIELD OF THE READING that a declaration names — never as a branch inside the machine. A run cannot judge its own liveness, so `in_flight` reaches the declaration and the kit's own row spells it; a host may declare a row that does not exclude it, and the projection carries the whole of it. An exemption nobody can see the other side of is indistinguishable from a blind spot, and it is also the shape of a gate with an exemption field — which is not a gate. |
| **Eval-driven development · LLM-as-judge · pairwise preference · HELM** | *named as references; deliberately NOT built* | The field's vocabulary is adopted (a case, a rubric, a judge, a verdict) and none of its CONTENT is. What HELM ships and this kit may not is the SCENARIOS: a benchmark is a domain's opinion about what matters, and a framework shipping one would judge every host by a standard it could not have known. |
| **The materialised blank** | *newly met, adopted* | An absence cannot be counted; a blank can. `evaluate` opens a record holding `UNJUDGED` for every declared pair that has none, so *never judged* is a dated record rather than a silence, and no surface can report it as fine. Slice G's write-ahead rule in a second subject — which is how it announces it was never about run receipts. |
| **Capability attestation — CLAIMED · PROVEN · ABSENT** | *adopted in its declarative half; the PROVEN half is a DECLARED GAP with a name* | A runtime's capabilities are not known, they are proven. So three states, and every declared capability is PLACED in exactly one of them for every runtime, always — the vocabulary is declared first, which is the only reason an unclaimed capability can be a named absence instead of a silence. The descriptor schema is closed BY ABSENCE: there is no field a proof could be written in, so a host can state a belief and can never state an observation. What is **not built**: nothing in this repository yet writes a record naming a runtime AND a capability, so PROVEN is empty for every runtime — and the surface says *no source of proof is declared at all* rather than printing `0`, because a count taken where no instrument exists is an attribution that cannot fail, and an attribution that cannot fail certifies rather than measures. `composes.accounts.proven` is the declared seam a proof source will arrive through; it is deliberately absent from the shipped declaration rather than pointed at a reading that could not distinguish one runtime from another. Reference class: SLSA/in-toto attestations (a claim signed by whoever made it, never by the subject), OpenTelemetry receipts for the run half. |
| **Two disjoint schemas, and the rule the validator cannot see** | *adopted, price restated deliberately* | The bill L6 paid is paid again here and for the same reason: `runtime-class` and `runtime` share no vocabulary and both close with `additionalProperties: false`, so a host cannot write a second body — but *that the two are disjoint* is a rule no `$ref` and no validator holds, and only an acceptance test measures it (`test_106`). The alternative — one widened schema — was rejected because slice H already showed what widening costs: the meaning of the narrower half stops being expressible. A composed schema would be the third option and JSON Schema does not have one worth using here. |
| **A reference gate learns DEPTH as data, not as a second kind** | *newly met, adopted* | A record may point at a referent once or once per row of a list. That is a property of the record's SHAPE and not a different question, so `each` is a word in the reference's own declaration and the scan, the calibration and every word of the report stay identical. A second gate kind would have made the depth an interpreter's opinion about somebody else's record, and would have doubled again the day a third reach arrived. |
| **Three-way reconciliation (dpkg conffile · rpm `.rpmnew` · git 3-way merge)** | *partial, with the missing part named* | ADR-002. The full cell table is adopted WHOLE, with the refusals declared rather than resolved, and the locally-modified shipped file answered by a DOOR carrying a recorded name, moment and superseded digest instead of a prompt. Verified live by the orchestrator: an edited kit-owned file is KEPT and NAMED with both moments; the same file changed upstream too REFUSES the whole upgrade at exit 3 with the host's bytes untouched; `--approve <who>` writes `signed_by` and `superseded` onto the row. MISSING: consent is recorded against a path and a version, never against a CHANGE. NON-GOAL: the kit never archives superseded bytes — it refuses BEFORE the write, and the host's own VCS is the archive. |
| **The estate — a tree states what it IS and never what it RECEIVED** | *newly met, adopted* | `kit.lock.json` says what the KIT is and cannot say what a HOST was given; from inside a tree those two readings are indistinguishable. So the host keeps `.agents/project/estate.json`: every path it received, its class and mode, the owning capability, the digest of the bytes as they went down, the moment, and the name on the door. The reconciler computes only WHICH CELL three readings fall in; what a cell MEANS is declared by a steward, and a cell no steward answers is REFUSED rather than defaulted. |
| **A withdrawn file is ORPHANED, never deleted** | *newly met, adopted* | The first table had the kit delete a path the new version no longer ships. It cannot: a capability's `installs` IS its write permission, so a path the new kit does not declare is a path nothing gives it permission to touch. The file stays and its row stays, marked with the version that withdrew it — so it never becomes an unexplained path in a governed plane. The law wrote this cell, not the designer. |

## Rule earned here, stated without the vocabulary of its case

> **Half-built state is not partial success; it is unverified state.** A run that dies mid-way
> leaves artifacts that read exactly like finished ones. Six defects sat in the half of slice A
> written by a mind that never got to execute anything — including a template in the wrong
> language and a declaration class nobody validated. The cure is not vigilance: it is that
> nothing counts as built until it has been RUN, and that the first green is never trusted
> without an adversarial probe designed to make it fail.

> **A promise two mechanisms keep separately is not a promise; it is a coincidence with a good
> record.** A preview that recomputes what the real run will compute is correct exactly until
> someone edits one of them, and the failure is silent because both halves remain internally
> right. The cure is never diligence and never a review checklist — it is that there is only ONE
> decision, made once, printed by one caller and consumed by the other. Slice C's probe is the
> proof and the method: give the second half permission to decide for itself, and watch which
> assertions go red. If none do, the guarantee was never being measured.

> **A layer of judgement added above another must not answer first — and this is the second time
> it has happened.** Slice B: composition refused before the measurement it followed from could
> report. Slice C: looking up the answers file refused before the composition that explained why
> the declaration was missing. Same shape, different layer, so it is no longer an observation —
> it is a rule we are already paying for twice. A lookup that a later step needs is resolved
> LATE, where its absence is a real answer, never early where it merely happens to be convenient.

> **A projection is a reading, and a reading states the moment it was taken.** Whenever one
> artefact is derived from another that a human may author, there is a window in which the
> derived one is honestly obsolete — and a checker that reports this as a generic mismatch is
> naming a symptom where a state exists. The system already has the vocabulary for this: unbound,
> empty, stale, partial are DECLARED states. `stale` is the one it declared everywhere except
> about itself. Met twice, in two unrelated capabilities, which is how a rule announces that it
> was never about either of them.

> **An attribution that cannot fail does not measure — it certifies.** The dangerous half of a
> passing gate is never the assertion; it is the SET the assertion was applied to. A harvest that
> yielded nothing, a seed nobody could judge, two hosts that happened to resemble each other —
> each passes gloriously while measuring an empty set, and reads exactly like a scan that looked
> and found nothing. So a sensor proves TWO things before it is believed: that it can see a
> crossing, and that it was pointed at something.

> **A width is an assumption, and an assumption at a boundary is a lie waiting for a longer
> name — and this is the second time it has happened.** The kit's plan report reserved a fixed
> number of characters for a declared name. The day a name was one character longer, two columns
> ran together, the row still read as a perfectly plausible row, and every reader — human and
> machine — parsed one field where there had been two. Nothing raised, nothing warned; three
> assertions simply began comparing a set that had quietly lost four of its members. It is the
> same shape as the line ending that was normalised on somebody else's machine: a boundary
> believed rather than measured, staying correct exactly as long as nobody stood at the edge of
> it. Seen twice, so it is no longer an observation. Every dimension of a rendered surface — a
> width, a separator, an encoding, a limit — is DERIVED FROM THE DATA it must carry, or it is a
> guess that will one day be wrong silently.

> **A record written only at the end proves nothing about a run that never reaches the end.** The
> artifacts of a run that died read exactly like the artifacts of a run that finished, and no
> amount of looking at them will separate the two — the difference is not in what was produced, it
> is in whether anything was ever CONCLUDED, and only the run itself could have said that, and
> only before it stopped being able to. So the trace is opened before the work and closed after
> it, and the close is the part that is allowed to be skipped. Everything that reports on a
> process from outside it inherits this: a status computed at the end is a status that exists only
> for the runs that did not need it. This slice was designed inside its own subject — the previous
> attempt at it was killed mid-way and left five finished-looking files that had never been run —
> which is the only reason the rule is stated here as an identity rather than as a nice idea.

> **A surface that says nothing when nothing was declared is indistinguishable from one saying
> everything is fine.** The two states are opposite and the rendering is identical, so the reader
> supplies the difference from their own optimism — and supplies it in exactly the direction that
> stops them looking. The cure is not a warning banner: it is that the ABSENCE is given a name, a
> record and a count, so it occupies space on the surface proportional to what is missing. Every
> zero in this system is a declared zero, or it is a lie waiting to be believed.

> **A refusal must stop the WHOLE operation, never the path.** Skipping the one thing that could
> not be reconciled and applying the rest leaves a tree in a state no version describes — neither
> the old one nor the new one, and nothing on disk says which. The partial application is worse
> than the failure it was trying to survive, because the failure was legible. Every mechanism that
> can refuse must refuse entirely, in the plan, before a byte moves.
