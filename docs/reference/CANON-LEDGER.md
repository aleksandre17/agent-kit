# Canon Ledger — met concepts and declared gaps

> **Kind: REPORT.** This register records what the work MET, in the session it was met.
> It declares nothing binding on its own; a row becomes law only by restatement in an ADR.
> It grows in two directions: **upward** (a concept rising to its home) and **inward**
> (a question the design could not answer, declared *before* it is improvised around).
> A register whose rows never leave it has become a graveyard.

## Gaps — questions the design could not answer

Declared at the moment they were met. An improvised answer is allowed; an improvised answer
that leaves no trace is not.

| Gap | Met | Status |
|---|---|---|
| **An uninstalled host has no declared state.** The design has vocabulary for an *unavailable capability* and none for *"the kit is not installed here"* — only an absence. `init` exits non-zero and names the unmet fact, so the surface does not lie; but `check` afterwards reports the missing `project.json` rather than the unmet requirement that caused it, so the *second* reading names a symptom where the first named the cause. | 2026-09-09, slice A, `test_10` | OPEN |
| **`project.schema.json` requires `capabilities` with `minItems: 1`**, structurally forbidding a host that legitimately enables none. The schema encodes an optimism the mechanism does not require. Changing a BINDING schema was out of slice. | 2026-09-09, slice A | OPEN — **reframed, slice C.** With `never_disabled` now read, a set with no capabilities is unreachable through the selection mechanism, so `minItems: 1` no longer encodes optimism the mechanism does not require: it encodes something the mechanism now enforces. Two homes for one truth, and the schema's is the one nobody can date. Still open, and now for the sharper reason. |
| **When has an interpreter's vocabulary become a privileged name?** The install modes (`seed` · `reading` · `declaration`) carry no proper noun and are generic — yet they are the closest thing to policy inside the interpreter, and Cardinal IV offers no test for the boundary. The proper-noun grep passes; the question it answers is narrower than the question that matters. | 2026-09-09, slice A | OPEN |
| **The kit does not ship itself.** `.agents/kit/` receives only what a capability declares, so `__pycache__` appeared *inside the payload* the first time the kit ran — the unclassed-state condition the layout proposal diagnoses, reproduced by the kit against itself. The declared cure is manifest-enumerated shipping via `kit.lock.json`, out of slice A. Fenced with `.gitignore` and named here rather than smuggled in early. | 2026-09-09, slice A | OPEN — cure named, deferred |
| **Schemas cannot compose.** `validation.py` implements no `$ref`, so no schema may reference another. Adequate for every schema in the kit today; it will bite at `role.schema.json`, where a role composes an archetype. | 2026-09-09, slice A | OPEN — dated trigger |
| **A capability may install outside every declared plane, and nothing classes it.** `knowledge` installs into `docs/`, which is MADR's canonical home and correctly NOT `.agents/`. Its files get a class from their exact target declarations, but `FF-KIT-CLASS` walks `.agents` only, so under `docs/` there is no totality: a stray file there resolves to no class and no gate says so. Extending class-totality to `docs/` was refused deliberately — it would forbid the host from keeping any document the kit did not declare, which is not the kit's business. The real question the design cannot answer: **what is the class of a path the framework writes into but does not own?** | 2026-09-09, slice B | OPEN |
| **"Append-only, immutable once accepted" is doctrine with no gate.** `docs/decisions/` declares, and an accepted ADR is supposed to be superseded rather than edited. Nothing measures that: the kit sees one filesystem state and has no history, so an edited decision is indistinguishable from one that always said this. Any cure needs a recorded prior reading (content digests in a lockfile, or git history read through a port) — both deferred with `kit.lock.json`. Until then the rule binds humans and no machine, and the ledger says so rather than the ADR implying otherwise. | 2026-09-09, slice B | OPEN — cure named, deferred |
| **Approval is a moment, not an identity.** `--approve <who>` writes `signed_by` verbatim: the kit records the string it was handed and cannot tell an owner from an automation from a typo. The acceptance suite signs as `acceptance-suite` and the answers file reads exactly as an owner's would. So P3 proves that *someone deliberately passed the door*, which is a real guarantee, and it does NOT prove *who* — a door that cannot recognise a face records attendance, not consent. Any cure crosses a boundary the kit has no port for (a VCS identity, a signature, a review). Named rather than implied by the field's name. | 2026-09-09, slice C | OPEN |
| **A host may change its mind, and nothing uninstalls.** Selection is expressible only *before* the first answer; afterwards the answers file is the truth and `--enable/--disable` are refused against it. Editing that file to drop a capability therefore removes it from the enabled set while every file it already wrote stays on disk, owned by a capability the host no longer runs. `FF-KIT-CLASS` does not catch them: class declarations come from the whole MANIFEST, not from the enabled set, so an orphan still resolves to exactly one class and reads as legitimate. The kit can add a capability by choice and cannot subtract one. | 2026-09-09, slice C, met while writing `_chosen` | OPEN — needs `upgrade`, deferred |
| **`never_disabled` is a declaration nobody reads.** `MANIFEST.json` marks `governance` as never disabled; no interpreter consults the flag, because there is no selection mechanism for it to constrain — a capability is enabled iff its requirements are met. The flag anticipates a host CHOOSING its set, which does not exist yet. A declared field with no projection is exactly the drift Cardinal III warns about, only pre-emptive: it reads as enforced. Either a selection mechanism arrives and reads it, or the field goes. | 2026-09-09, slice B | **CLOSED**, slice C — the field LIVES and is read by `resolver.select`. Ruled on rather than kept: `governance` owns the host's reading, its answers file and the gates that class every path, so a set without it has no way to describe itself. It stays on the MANIFEST ENTRY, not in the capability: a capability declaring itself indispensable would be granting itself authority, and which of its own parts a kit cannot stand without is a statement the KIT makes. Evidence is a DIFFERENCE, not a message — `test_32` runs one command against two kits differing only in that field and gets two different refusals, so the flag is provably what fires. |
| **Composition is proved for a set the KIT declares, never for one a HOST chose.** Every composition case in slice B is built by patching a fixture manifest, because a host cannot yet enable or disable anything. `requires`, `provides`, `conflicts`, ordering and shadowing are therefore proved as properties of *declarations*, not of *host choice* — and the difference is where the interesting failures live (a host disabling a capability something else needs). | 2026-09-09, slice B | **CLOSED**, slice C — the host chooses, and the choice has one home: `--enable/--disable` author the answers file before it exists, and afterwards the answers file IS the set and a contradicting flag is refused (`test_34`). `test_30` asserts a subset BOTH ways — the chosen capability's paths present, every path of the excluded one absent, its whole plane gone. `test_31` reaches the case slice B could not: a host that drops a capability another REQUIRES is refused, told which CHOICE caused it (`which this host chose to disable`, distinct from the measured `which this host cannot support`), and the host is asserted byte-empty afterwards. |
| **A projection over a host-authored binding is stale the instant the host authors**, so `check` is red between authoring and `render`, and the doctrine says whose duty it is to close that window nowhere. Met in delivery, met AGAIN in hygiene, which had to run `render` first in two tests to work around it. Candidate resolutions, none chosen: (a) `check` declares projection-staleness as its own named state instead of a generic byte-diff failure; (b) a `stale` disposition reporting the moment of the last render; (c) `check` refuses to judge a projection whose inputs are newer than it. | 2026-09-09, slices D and E | OPEN — **seen twice, so it is no longer an observation.** The rule it earned is stated below; the mechanism that would enforce it is still unbuilt. |
| **May a residence rule ever be enforced by REMOVAL under human sign-off?** The `move`-style door exists for cards and not for files. `hygiene` answers "never" locally — a capability's choice standing in for a doctrine that is silent, which is exactly the shape Cardinal VI says to declare rather than improvise past. | 2026-09-09, slice E | OPEN |

## Canon met — status per Law 13

| Concept | Status | Note |
|---|---|---|
| **Mustache (logic-less templating)** | *adopted as a NAMED SUBSET* | Sections, inverted sections, dotted paths, standalone-line stripping. Refuses partials, lambdas, `{{{ }}}`. **Deviation named:** a missing key RAISES rather than rendering empty — the projection plane may not lie (Cardinal V). This refusal is what exposed a `.mustache` file that was actually Handlebars. |
| **Ports & Adapters** | *adopted whole* | `Manifest · Workspace · Probe · Clock` at the verb boundary. |
| **Capability-declared write scope** (least privilege / object-capability) | *newly met, adopted* | A capability's `installs` list is simultaneously its manifest AND its permission set. A second home for that truth is impossible because it is one list. This is our addition beyond the ports pattern. |
| **JSON Schema** | *partial, missing part NAMED* | No `$ref`, no combinators. Unsupported keywords are refused loudly rather than ignored — a validator that silently skips what it cannot check is worse than none. |
| **Debian conffile / copier answers-file** (create-once host truth) | *adopted in part* | Realised as the `seed` / `reading` / `declaration` install modes. The lockfile half is proposed, not built. |
| **Git end-of-line normalisation as a measured boundary** | *adopted* | The kit asserts `render` is byte-reproducible; the first commit emitted 26 LF→CRLF rewrites. Both git and the renderer behaved correctly and the guarantee was false outside this machine — while still reading as true from inside, because the local test passed. `.gitattributes` pins LF everywhere. **Cardinal VII, found in this repository's own first commit.** |
| **FF-KIT-SECOND-HOST** | *built and GREEN* | The framework's central claim — that it is portable — is now measured rather than asserted. Eleven assertions against a scratch repository it has never met. |
| **Diátaxis × MADR × the Kind Law** | *adopted, crossed* | Diátaxis says what a document is FOR; MADR says how a decision is RECORDED (canonical `docs/decisions/`, adopted rather than invented); the Kind Law says what a LOCATION may grant. The cross is the capability: authority is a property of location, never of prose, so the gate reads a name and a path and never a word of content. |
| **Dependency resolution (topological, total order)** | *adopted whole* | Kahn with a sorted frontier: dependencies first, ties by id, result independent of declaration order — asserted by reversing the manifest and demanding the same emitted order. |
| **Provision over identity (substitutability)** | *newly met, adopted* | A `requires` of kind `capability` matches what capabilities **provide**, never their ids; a capability's own id is not an implicit provision, because a name is not a contract. Measured both ways: renaming the provision breaks the requirer, renaming it on both sides installs cleanly. |
| **Shadowed path = defect, not precedence** | *newly met, adopted* | Two capabilities installing to one path is refused before the first byte, naming both owners. There is no last-writer-wins and there must never be one: the loser's declaration would go on reading as true while the bytes came from elsewhere — both locally correct (Cardinal III). |
| **Measurement is reported before composition refuses** | *earned in slice B* | Adding a capability-level requirement silently swallowed slice A's honest `unavailable governance` report: the refusal fired first and named the consequence. The cure was structural, not a weakened assertion — `classify` (measures, never refuses) is separated from `compose` (refuses, never measures), and the caller reports between them. **The general rule: when a new layer of judgement is added above an existing one, the existing one's report must still reach the surface first — a cause that arrives after its consequence is not a report, it is a correction nobody asked for.** |

| **Terraform plan/apply** | *newly met, adopted whole* | `--plan` is a FLAG on every verb that declares `MUTATES`, never a sixth verb, and it is not a preview: the verb DECIDES once and the plan and the apply are the same value, entry by entry. Each install mode has two halves — FORESEE (what would happen) and APPLY (which is handed the answer and decides nothing). Measured by comparing a plan run's rows against the apply run's lines (`test_36`, `test_37`), and by a mutation probe: making the apply decide for itself turns two slice-A assertions red. |
| **Copier's answers file** | *promoted from "in part" to adopted* | Slice B had the create-once install modes; the half that was missing was the ANSWER. `project.json` is now what the HOST chose, authored by `--enable/--disable` exactly once and thereafter the source of truth, with a flag that contradicts it refused rather than obeyed. |
| **The unanswered case as a declared state** | *newly met, adopted* | An install whose approval never came is `status: draft`, DATED, on disk, and every verb declaring `REQUIRES_APPROVED_HOST` refuses while it stands, naming the date. It carries its own exit code (3), because a stalled install is not a broken one and an operator who cannot tell them apart will either ignore real defects or re-run a refusal forever. Cardinal V at the one door in the design. |
| **Verb-declared preconditions** | *newly met, adopted* | `MUTATES` and `REQUIRES_APPROVED_HOST` are declared BY each verb and read generically by the CLI, which still knows no verb's name. Asking a non-mutating verb for a plan is refused rather than answered with an empty one — an empty plan reads as "nothing to do", which is a different statement from "this verb never writes". |
| **Residence / the calibrated sensor** | *adopted whole* | Declared by `kit/capabilities/hygiene/residence.json` and read by `gates/hygiene.py`. A genre of document that has no home is a DECLARED row — pattern, reason, destination — and each row carries its own calibration: one path it MUST match and one lookalike it MUST NOT. If any rule fails its calibration the tree is NOT SCANNED AT ALL and the uncalibrated rule is the finding. A sensor that has not proved what it sees may not report on the tree, still less act on it. |
| **Sensor and actuator, separated** | *adopted whole* | `hygiene` NAMES residents and cannot remove one: no write, and no port through which a write could be reached. The slice's label was wider than its honest content, and the narrower thing was built. |

## Rule earned here, stated without the vocabulary of its case

> **Half-built state is not partial success; it is unverified state.** A run that dies mid-way
> leaves artifacts that read exactly like finished ones. Six defects sat in the half of slice A
> written by a mind that never got to execute anything — including a template in the wrong
> language and a declaration class nobody validated. The cure is not vigilance: it is that
> nothing counts as built until it has been RUN, and that the first green is never trusted
> without an adversarial probe designed to make it fail.

> **A promise two mechanisms keep separately is not a promise; it is a coincidence with a good
> record.** A preview that recomputes what the real run will compute is correct exactly until
> someone edits one of them, and the failure is silent because both halves remain internally
> right. The cure is never diligence and never a review checklist — it is that there is only ONE
> decision, made once, printed by one caller and consumed by the other. Slice C's probe is the
> proof and the method: give the second half permission to decide for itself, and watch which
> assertions go red. If none do, the guarantee was never being measured.

> **A layer of judgement added above another must not answer first — and this is the second time
> it has happened.** Slice B: composition refused before the measurement it followed from could
> report. Slice C: looking up the answers file refused before the composition that explained why
> the declaration was missing. Same shape, different layer, so it is no longer an observation —
> it is a rule we are already paying for twice. A lookup that a later step needs is resolved
> LATE, where its absence is a real answer, never early where it merely happens to be convenient.

> **A projection is a reading, and a reading states the moment it was taken.** Whenever one
> artefact is derived from another that a human may author, there is a window in which the
> derived one is honestly obsolete — and a checker that reports this as a generic mismatch is
> naming a symptom where a state exists. The system already has the vocabulary for this: unbound,
> empty, stale, partial are DECLARED states. `stale` is the one it declared everywhere except
> about itself. Met twice, in two unrelated capabilities, which is how a rule announces that it
> was never about either of them.
