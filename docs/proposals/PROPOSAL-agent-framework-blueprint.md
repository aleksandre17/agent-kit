# ნაწილი I — შვიდი დონე

დამოკიდებულების ისარი შიგნით იყურება. ქვედა დონემ არ იცის ზედას არსებობა.

```
  L0  ═══ იდენტობა ═══════════════════════════════════════════════ არაფერზეა დამოკიდებული
      CARDINALS.md — რვა იდენტობა. უდროო. არცერთი პროექტის ლექსიკა.
```

**ორი წესი, რომელიც დონეებს იცავს:** `L3` `L2`-ის შიგთავსს პრივილეგირებულად ვერ კითხულობს — ის მას *ინტერპრეტირებს*; `L2` ქცევას ვერ ატარებს. **Cardinal IV-ის ორი ნახევარი; ცალკე არცერთი მუშაობს.**

### შესწორება ① — ეს არაა ერთი ღერძი, ორია. ნახაზი ამას მალავდა.

L0→L3 არის **დონეები**: მიმართება *„დამოკიდებულია"*, ისარი შიგნით. L4→L7 არის **კლასები**: მიმართება
*„წარმოებულია"* + *„ვინ წერს, რას შვება upgrade"*. ერთი სიტყვით ორი მიმართების დარქმევა Cardinal III-ის
დეფექტია: ორივე ლოკალურად სწორია, კონტრადიქცია არსაიდან ჩანს. **საზღვარი ღერძის გადართვის წერტილია.**

დონე არც ერთით მეტია, არც ერთით ნაკლები. მაგრამ **L4 არ არის კლასგარეშე** — და-დოკუმენტი აცხადებს,
რომ `profile.json` **BINDING**-ია, რადგან ადამიანს გაზომილი ფაქტის შესწორება შეუძლია. აქედან:

> **L4 და L5 ერთი კლასია ([B]), ორი წარმომავლობით:** L4 = `provenance: measured`, L5 = `provenance: declared`.
> წარმომავლობა იწერება ველად, არა ფოლდერით. ორივე ატარებს ბეჭედს. `check` ადარებს ჩაწერილ
> წაკითხვას ახალ ზონდირებას და **განსხვავებას აცხადებს, არ გადააწერს** — გაზომვა ატყობინებს, არ ბრძანებს.

# ნაწილი II — რატომ „შესაძლებლობა", და რა აკლია მას დღეს

**ერთეული სწორია.** ველზე იგივე ჰქვია: Debian `Package`, Helm subchart, Terraform module, Backstage
plugin, Cargo feature — *„დეკლარირებული ერთეული, რომელიც ჩრდილს აგდებს ხეზე"*. „template/preset" სუსტია:
ერთჯერადი ანაბეჭდი, არა კომპოზირებადი ერთეული — კომპოზიციაა ის, რაც ჩარჩოს ჩარჩოდ აქცევს.

**მაგრამ `requires · installs · declares · gates` არასრულია:** **კომპოზიციის სემანტიკა არსად არაა
გამოცხადებული.** სამი დამატება, თითოეული ველიდან:

```
 requires:  [{cap|fact, range}]   Debian Depends + semver — ვერსია, არა მხოლოდ სახელი
 provides:  ["virtual-id"]        ★ ვირტუალური შესაძლებლობა: ორმა სხვადასხვამ შეიძლება
                                   ერთი მოთხოვნა დააკმაყოფილოს. ეს არის Cardinal II
                                   კონსტრუქციით — მოთხოვნა სახელს არ აპრივილეგირებს.
 conflicts: ["cap-id"]            გამოცხადებული შეუთავსებლობა, არა აღმოჩენილი
 installs:  [path-pattern + class]  ★ ეს არის *ჩაწერის არეალიც* — იხ. ნაწილი VII
```

**და რეზოლვერი უნდა გამოცხადდეს, თორემ „requires" სურვილია:**

| შემთხვევა | გამოცხადებული ქცევა |
|---|---|
| წრე (A→B→A) | **ჩერდება.** სახელდებული შეცდომა ციკლის ბილიკით. არასდროს „საუკეთესო მცდელობა". |
| დაუკმაყოფილებელი `requires` | შესაძლებლობა **მიუწვდომელია, მიზეზით** (P2). არასდროს ჩუმი გამოტოვება. |
| ორი `provides` ერთ id-ზე | **ორაზროვნება = არაფერი.** მფლობელი ირჩევს P3-ზე; ავტომატური არჩევანი აკრძალულია. |
| ორი შესაძლებლობა ერთსა და იმავე გზას აგდებს | ★ **ჩრდილების შეჯახება = დეფექტი, არა უკანასკნელი მოგებული.** გამოცხადებული `conflicts` ან სხვადასხვა გზა. |
| რიგი | დეტერმინისტული ტოპოლოგიური დალაგება, ტოლების დროს id-ის ლექსიკოგრაფიული. **ერთი შეყვანა → ერთი ხე, ყოველთვის.** |

**კომპოზიციის კანონი (Cargo feature unification, მთლიანად მიღებული):** ნაკრები **მხოლოდ მატებადია** — ერთის ჩართვა მეორეს ჩრდილს არ ართმევს. გამზომი: `render({A})` ∪ `render({B})` ⊆ `render({A,B})`.

### შესწორება ② — მიმდევრობა, რომელიც მხოლოდ ბედნიერ ბილიკზე მუშაობს, ესკიზია

ხუთი მტრული კითხვა; სამი პასუხი **ახალი მექანიზმია**, არა განმარტება.

| მტრული კითხვა | გამოცხადებული პასუხი |
|---|---|
| ფაზა ჩავარდა შუაზე | ★ **ჟურნალი.** `init` თითოეულ ფაზას ჩაწერს *დაწყებამდე* და *დასრულების შემდეგ* `runtime/init.journal`-ში. მდგომარეობა გარეთ ინახება, სანამ დაიკარგება (Cardinal V: დუმილი ყველაზე საშიში ტყუილია). ხელახალი გაშვება **აგრძელებს**, არ იწყებს. |
| `init` ორჯერ გაეშვა | `init` **იდემპოტენტურია ჟურნალის მოდულო**. დასრულებულ რეპოზე `init` არაა ხელახალი ინიციალიზაცია — ის `render` + `check`-ია (copier-ის update-სემანტიკა). „ხელახლა ინიციალიზაცია" ცალკე, გამოცხადებული, დამანგრეველი მოქმედებაა. |
| ორი runtime ერთდროულად | ★ **დამჭერიანი საკეტი:** `runtime/init.lock` ატარებს მფლობელს, pid-ს და დროის ბეჭედს. მოძველებული საკეტი (> N წთ) **გამოცხადებით** ტყდება. საკეტი მფლობელისა და ასაკის გარეშე დედლოკის გენერატორია, არა დაცვა. |
| რეპო ცარიელი არაა | ★ **მიღების (adoption) ფაზა P4-ის წინ.** არსებულ გზას, რომელსაც ჩრდილი ედება, არ აქვს კლასი — ის `foreign`-ია. `foreign` არ შთაინთქმება და არ გადაიწერება: ის **ჩერდება სიით**. ეს იგივე ხვრელია, რაც და-დოკუმენტის `locally-modified`, ოღონდ ინსტალაციის დროს. |
| მფლობელმა P3-ს არ უპასუხა | draft დისკზე, დათარიღებული; P4+ უარს ამბობს. არაფერი გრძელდება „ნაგულისხმევით". |

**ერთი ღია პირობა:** `observe → enforce` ზღვარი **რიცხვია, არა განცდა** (მაგ. *N დამოწმება M დღეში, ნული ცრუ-დადებითი*). უმისოდ „ქვითრებიდან გამოყვანა" ლოზუნგია; ქვითარს სქემა სჭირდება.

# ნაწილი VII — რაც ნახაზში საერთოდ არ იყო და ველზე სავალდებულოა

ოთხი აბსოლუტური ნაკლი; თითოეული სახელდებული მექანიზმია, არა სურვილი.

**① ნდობა და ჩაწერის არეალი — ყველაზე დიდი ხვრელი.** ჩარჩო ჩამაგრებულ **შესრულებად hook-ებს** დებს რეპოში, მფლობელის უფლებებით; `kit.lock.json` ფაილებს
ამოწმებს — **რელიზს არა**. საჭიროა: (ა) რელიზის ხელმოწერა წარმომავლობით (sigstore/SLSA) და
(ბ) **`installs` = ჩაწერის არეალი** `Workspace` პორტით — შესაძლებლობა ჩრდილის გარეთ ვერ წერს
(capability-based security, უფასოდ: ჩრდილი უკვე გამოცხადებულია).

**② L1 სქემების თავსებადობის პოლიტიკა.** მთელი სისტემა contract-first-ია, კონტრაქტს კი ვერსია არ აქვს. საჭიროა semver + **expand-contract**:
ახალი აუცილებელი ველი არასდროს ემატება — ჯერ არააუცილებელი, მერე მიგრაცია, მერე შევიწროება.
★ ეს **ნახევრად ხურავს** და-დოკუმენტის GAP-ს; ღია რჩება **დოქტრინის ტექსტის** ვერსირება (ნაწილი X).

**③ დიაგნოსტიკის მოდელი.** `check` „აცხადებს და არ არემონტებს" — მაგრამ მანქანით წაკითხვადი კოდების გარეშე ანგარიში ვერც CI-ს
კვებავს, ვერც P9-ს. საჭიროა შეცდომების ტაქსონომია სტაბილური კოდებით (rustc/ESLint/Terraform) +
exit-code კონტრაქტი. დღეს ქვითარს დასაწერი არაფერი აქვს: შედეგს სახელი არ აქვს.

**④ `--plan` ყოველ მუტაციაზე.** `init` და `upgrade` უცხო რეპოს ცვლიან; Terraform-ის plan/apply კანონიკური პასუხია: **მუტაცია ჯერ
აჩვენებს, რას გააკეთებს.** ეს მეექვსე ზმნა არაა (ხუთი რჩება) — დროშაა, გამოსავალით ②-ის სქემაში.

# ნაწილი VIII — ინტელექტის ღერძი: ქვითარი ამტკიცებს, რომ ისროლა — არა რომ მოარტყა

მთელი ნახაზი აქამდე **პროგრამული დისტრიბუციაა** და როგორც ასეთი — სწორი. მაგრამ:

> **ქვითარი ამტკიცებს, რომ ჭიშკარი ჩაირთო. ის ვერასდროს ამტკიცებს, რომ გადაწყვეტილება კარგი იყო.**
> L7 დღეს ორ სხვადასხვა ჭეშმარიტებას ერთ სახელს არქმევს — **სიცოცხლეს** და **ხარისხს**. ეს Cardinal III-ის
> ზუსტი ფორმაა: ორივე წაკითხვა ლოკალურად სწორია, და მარყუჟი იკვრება „ეშვება?"-ზე, არასდროს „უმჯობესდება?"-ზე.

**ეს არაა ახალი დონე და არაა მიბჯენილი სექცია — ეს L7-ის შესწორებაა + ერთი ახალი L2 შესაძლებლობა.**
```
  L7  ═══ დაკვირვება ═══ [E] ═══ ორი სიბრტყე, ერთი კლასი ══════════════════════════
      L7·ს  სიცოცხლე   receipts/ · telemetry/ · init.journal
                       სუბიექტი = **სისტემა**.  კითხვა: ჩაირთო?
      L7·ხ  ხარისხი    eval-runs/ · route-outcomes.jsonl
                       სუბიექტი = **დეკლარაცია** (როლი · ბარათი · მარშრუტი).
                       კითხვა: უკეთესი გახდა?
      ↳ ორი უკუისარი, არა ერთი:
        L7·ს → P9   ჭიშკარი კბენას იწყებს          (არსებული)
        L7·ხ → L5   დეკლარაცია ხდება `accepted`    ★ ახალი — იხ. ქვემოთ
```

**რატომ ცალკე შესაძლებლობა `evaluation`, არა `observability`-ის გაფართოება.** სხვა სუბიექტი = სხვა
ცვლილების მიზეზი (SRP/ISP): observability *სისტემას* აკვირდება და host-ს ბლანკს არ სთხოვს; evaluation
*დეკლარაციას* სჯის და `requires: [observability]`, რადგან განაჩენი ქვითრის ფორმით იწერება.

### „კარგი" არის host-ის ჭეშმარიტება. ჩარჩო აგზავნის განსჯის *გრამატიკას*, არასდროს — განაჩენს

`project/evaluation.json` — [B], `provenance: declared`. ჩარჩო მას **ბლანკად** აგდებს (T2 ძალაშია).

```jsonc
{ "$schema": "kit/schemas/evaluation.schema.json", "status": "draft",
  "suites": [{
    "id": "architect-judgement", "subject": { "kind": "role", "ref": "roles/architect.md" },
    "cases": [{ "id": "C1", "packet": "cases/C1.packet.json",       // შეყვანა — მონაცემი, არა კოდი
       "assert": [{ "strategy": "deterministic", "expr": "output.adr.rejected >= 2" },
                  { "strategy": "rubric", "rubric": "cases/C1.rubric.md", "floor": 0.7 }] }],
    "judges": [{ "id": "rubric", "strategy": "llm-rubric", "runs": 3, "aggregate": "median" },
               { "id": "pairwise", "strategy": "llm-pairwise", "against": "accepted" }],
    "promotion": { "no_case_below": "accepted", "min_cases": 5, "owner_signature": "required" } }] }
```

**გაყოფა, რომელიც ამას აკანონებს:** `strategy` **id-ია L2 რეესტრიდან** — ინტერპრეტატორი ჩარჩოსია.
`rubric` · `packet` · `floor` · `min_cases` — **host-ის ტექსტი და რიცხვია**. ჩარჩომ არ იცის, რა არის კარგი ADR;
მან იცის, როგორ ტარდება წყვილადი შედარება. Cardinal IV: დეკლარაცია არ სჯის, ინტერპრეტატორი პოლიტიკას არ ირჩევს.

### დეკლარაციის დაწინაურება — ჯაჭვი, რომელიც დღეს არ არსებობს

```
  შემოთავაზებული ედითი roles/architect.md-ზე
        ▼  candidate = sha256(ტექსტი) + semver ↦ roster.json (accepted-ის გვერდით, არა ნაცვლად)
  ① `check --eval <suite>`  ეშვება ორივეზე: accepted და candidate  ← expand-contract, იგივე რაც L1 სქემაზე
        ▼
  ② განაჩენი ↦ L7·ხ eval-run ქვითარი (suite · case · judge · ქულა · შეყვანის sha · ბეჭედი)
        ▼
  ③ ჭიშკარი **PROMOTION**: ვერცერთი case ვერ ჩავარდა floor-ქვემოთ ∧ min_cases დაკმაყოფილდა
        ▼                   ჩავარდნა = candidate რჩება candidate-ად, სახელით და მიზეზით
  ④ **მფლობელი ხელს აწერს** → `accepted` (P3-ის იგივე ერთადერთი კარი). მანქანა არ აწინაურებს.
```

**გაზომილი ჩავარდნა, რომელსაც ეს კრძალავს (არა ჰიპოთეტური):** დღეს ორი `architect.md` არსებობს და
**ერთმანეთს ეწინააღმდეგება tier-სა და tools-ზე** — ვერსიის გარეშე დეკლარაცია ჩუმად გაორდა და ვერცერთ
წაკითხვას ვერ უჩანს, რომ მცდარია (Cardinal III). ჭიშკარი `FF-DEFN-ONE-ACCEPTED`: ერთ subject-ს ერთი
`accepted`; ყოველი სხვა candidate-ია და ცხადად ასეთი.

### განაჩენი OpenTelemetry-ზე: **ვახვევთ, არ ვცვლით**

OTel GenAI semconv **ლექსიკონია, არა ტრანსპორტი**. jsonl ნაკადები რჩება ([E], gitignored, ნულოვანი
დამოკიდებულება — უცხო რეპოში ეს უპირატესობაა), მაგრამ **ატრიბუტების სივრცე OTel-ისაა**
(`gen_ai.operation.name` · `gen_ai.request.model` · `gen_ai.usage.*` · span/trace/parent id).
ღირებულება: mapping-ცხრილი + `route-outcomes.jsonl`-ის ველების გადარქმევა expand-contract-ით.
სარგებელი: ნებისმიერი collector კითხულობს ჩვენს კვალს ადაპტერის გარეშე. სრული ჩანაცვლება უარყოფილია —
collector-ის მოთხოვნა `fresh-repo` acceptance-ს გარემოზე დამოკიდებულს ხდის. ძირეული კანონი 4
სტანდარტს მთლიანად ითხოვს: მთლიანად ვიღებთ მის **კონტრაქტს**, არა მის ინფრასტრუქტურას.

**ტოპოლოგია — სახელი, რომელიც უფასოა.** `route.py` **contract-net protocol-ია** (Smith 1980)
ერთბიდიან ფორმამდე დაყვანილი, supervisor-ის ქვეშ; `route-outcomes.jsonl` მისი ბიდ-ისტორიაა.
**უსახელო ნიმუშს ვერც შეედავები, ვერც შეცვლი** (Cardinal II) — სახელდება მექანიზმს არ ცვლის,
ალტერნატივას (blackboard · swarm) გახსნის საგნად აქცევს.

# ნაწილი X — ხარვეზები (GAP), გამოცხადებული და არა შემოვლილი

Cardinal VI: რასაც დოქტრინა ვერ პასუხობს, ცხადდება იმ წამს, როცა შეგვხვდა.

- **GAP — დოქტრინის თვით-ვერსირება.** (და-დოკუმენტიდან; ნაწილი VII② სქემის მხარეს ხურავს.) ღია რჩება
  ტექსტი: upstream ცვლის Cardinal-ს, host-ის კანონში იცვლება ტექსტი, რომელიც მას არ დაუწერია —
  **თანხმობის არტეფაქტი არ არსებობს.**
- **GAP — ლეგიტიმურად ლოკალურად შეცვლილი [V] ფაილის მდგომარეობა.** (და-დოკუმენტიდან, ღია.)
- **GAP (ახალი) — `foreign` გზის მდგომარეობა.** ოთხკლასიან ნაკერს სახელი არ აქვს არსებული გზისთვის,
  რომელსაც ჩრდილი ედება და წარმომავლობა უცნობია. ნაწილი III მას *ჩერდებაზე* აყენებს — ეს ინსტალაციის
  ქცევაა, არა კლასი; მეხუთე კლასი და-დოკუმენტის გადაწყვეტილებაა და აქ ცალმხრივად არ იცვლება.
- **GAP (VIII) — ვინ სჯის მსაჯულს.** `llm-rubric`/`llm-pairwise` თვითონაა შესაფასებელი დეკლარაცია;
  მეტა-შეფასება (მსაჯულის თანხმობა ადამიანის ნიმუშთან) დოქტრინაში არსად წერია — უმისოდ „ხარისხის
  ქვითარი" იმავე ნდობის ხვრელშია, რაშიც ჩამაგრებული hook იყო ნაწილი VII①-მდე.
- **GAP (VIII) — ჩარჩო ნაგულისხმევ eval-ნაკრებს ვერ აგზავნის.** კარგი პასუხი დომენურია (ნაწილი IV),
  ამიტომ cases და rubric host-ისაა: **ახალი host იწყებს ნულოვანი საზომით.** ბლანკი ამას აცხადებს, არ ხსნის.
- **GAP (ახალი) — `observe → enforce` ზღვარი რიცხვი უნდა იყოს, და ის რიცხვი არსად გამოცხადებულა.**
