# ADR-001 — ჩარჩოს ბლუპრინტი: შესაძლებლობა როგორც ერთეული, გაზომილი საზღვარი, გაყოფილი L7

- **სტატუსი:** Accepted (2026-09-09)
- **გადაწყვიტა:** მფლობელმა — „გეგმა სრულად სრულდება, მერე ძველი სისტემა იძულებით ერგება ახალს“
- **წყარო:** `docs/proposals/PROPOSAL-agent-framework-blueprint.md` (რა ვაშენებთ) და
  `docs/proposals/PROPOSAL-agent-framework-layout.md` (როგორ დგას)
- **ცვლის:** ორივე პროპოზალი აქამდე `proposals/`-ში იდო — ანუ *გვთავაზობდა* და არ *აცხადებდა*.
  ჩარჩო მაინც შენდებოდა მათით. ეს ADR ხურავს იმ ხვრელს.

## კონტექსტი

ჩარჩო აშენდა A–D სლაისებით ბლუპრინტის მიხედვით, მაგრამ თვითონ ბლუპრინტი დაუმტკიცებელი
იყო და **სხვა რეპოში ცხოვრობდა** (`national-accounts`, გაყინული). ორივე დეფექტია:
პირველი — მშენებლობა დაუდასტურებელ საფუძველზე; მეორე — კარდინალი III, ჩარჩოს ჭეშმარიტება
მის რეპოს გარეთ.

## გადაწყვეტილება

ბლუპრინტის ოთხი ღია კითხვა დახურულია. ოთხივე **მიღებულია**:

### ① „შესაძლებლობა“ (capability) არის ჩარჩოს ერთეული

ველზე იგივე ერთეულია: Debian `Package`, Helm subchart, Terraform module, Cargo feature —
*დეკლარირებული ერთეული, რომელიც ჩრდილს აგდებს ხეზე*. „template/preset“ უარყოფილია:
ერთჯერადი ანაბეჭდი კომპოზირებადი არ არის, კომპოზიცია კი ის არის, რაც ჩარჩოს ჩარჩოდ აქცევს.

გრამატიკა სრული სახით: `requires` (cap|fact + semver დიაპაზონი) · `provides`
(ვირტუალური id — ორმა სხვადასხვამ შეიძლება ერთი მოთხოვნა დააკმაყოფილოს, ანუ მოთხოვნა
სახელს არ აპრივილეგირებს) · `conflicts` (გამოცხადებული, არა აღმოჩენილი) · `installs`
(გზის შაბლონი + კლასი, და იგივეა **ჩაწერის ნებართვა**).

რეზოლვერი გამოცხადებულია და არა ნაგულისხმევი: წრე **ჩერდება** სახელდებული ბილიკით ·
დაუკმაყოფილებელი `requires` → **მიუწვდომელი, მიზეზით**, არასდროს ჩუმი გამოტოვება ·
ორი `provides` ერთ id-ზე → **ორაზროვნება = არაფერი**, მფლობელი ირჩევს P3-ზე ·
ორი შესაძლებლობა ერთსა და იმავე გზაზე → **დეფექტი, არა უკანასკნელი მოგებული** ·
რიგი დეტერმინისტული, ტოლებზე id-ის ლექსიკოგრაფიული.
კომპოზიციის კანონი (Cargo feature unification, მთლიანად მიღებული) მხოლოდ-მატებადია:
`render({A}) ∪ render({B}) ⊆ render({A,B})`.

*მდგომარეობა: აშენებული და დამტკიცებული სლაისებით B და C.*

### ② პროცესი/დომენის ხაზი, გაზომილი T1–T3-ით

ხაზი ერთი წინადადებით: **ჩარჩო ფლობს ჭეშმარიტებას იმ პროცესზე, რომლითაც დომენი წყდება —
ვერასდროს თვით გადაწყვეტილებას.** ტესტი: *შეიძლება ამ არტეფაქტის შიგთავსი მცდარი იყოს ისე,
რომ მხოლოდ დომენის ექსპერტმა შეამჩნიოს?* თუ დიახ — ის დომენია, და ჩარჩო მხოლოდ ბლანკს დებს.

გემოვნება აქ არ წყვეტს; სამი გამზომი წყვეტს:

- **T1 · სახელის ტესტი** — `interpreters/`-ში საკუთარი სახელი (პროექტი · სტეკი · როლი ·
  runtime) დამთხვევა = დეფექტი. `[FF-KIT-PURE]`
- **T2 · ბლანკის ტესტი** — ყოველი გამოსხივებული ფაილი ვალიდურია და სასარგებლოა **ნულოვანი
  დომენური შიგთავსით**; თუ ის დომენზე უკვე ამბობს რამეს, საზღვარი გადალახულია.
- **T3 · ორი host-ის ტესტი** — ორ მაქსიმალურად განსხვავებულ რეპოში ინსტალაცია, L6-ის დიფი;
  **ყოველ განსხვავებას წინაპრად სჭირდება პროფილის ფაქტი ან P3-ის პასუხი.** განსხვავება
  წინაპრის გარეშე = დომენის გაჟონვა.

*მდგომარეობა: გამოცხადებული, ჯერ არ აშენებული — ეს არის `fitness` სლაისის შიგთავსი.*

### ③ ნაბიჯი 0 იწყება

რიგი შებრუნებადი არ არის და acceptance-first-ია: `fresh-repo` სუიტი იწერება ძვირი
მოძრაობის წინ, არა მის შემდეგ.

*მდგომარეობა: შესრულებული. სუიტი არსებობს და ის არის განვითარების მარყუჟი, არა საბოლოო
გამოცდა. `e051ac4`-ზე 42/42.*

### ④ L7 იყოფა სიცოცხლედ და ხარისხად

ერთი დონე ორ სხვადასხვა კითხვას ვერ პასუხობს. **სიცოცხლე** არის: გაეშვა, დასრულდა,
დატოვა კვალი. **ხარისხი** არის: კარგი იყო თუ არა. ეს უკანასკნელი დომენურია (ნაწილი IV),
ამიტომ:

> **ქვითარი ამტკიცებს, რომ ისროლა — არა რომ მოარტყა.**

ჩარჩო აგზავნის **განსჯის გრამატიკას** (rubric-ის ფორმა, eval-ის ზმნა, ქვითრის სქემა),
არასდროს — **განაჩენს**. cases და rubric ჰოსტისაა; ახალი ჰოსტი იწყებს ნულოვანი საზომით,
და ბლანკი ამას **აცხადებს**, არ ხსნის.

*მდგომარეობა: გამოცხადებული, ჯერ არ აშენებული — `observability` და `evaluation` სლაისები.*

## შედეგები

- ბლუპრინტსა და layout-ს **ერთი სახლი აქვს** და ის ჩარჩოს რეპოა. `national-accounts`-ში
  ასლი არ რჩება — ასლი არ სინქრონდება, ასლი იშლება.
- სლაისების რიგი ამ ADR-ის ქვეშ დგას: `hygiene` → `fitness` (② T1–T3) → `observability`
  → `evaluation` (④) → L6 როლების არქეტიპები → runtime დესკრიპტორები → `kit.lock.json`
  → `upgrade` ★ → `adoption` ★ → და მხოლოდ მერე `national-accounts` როგორც host #2.
- ორი ვარსკვლავი ატარებს დარჩენილი რისკის უმეტესობას: ისინი პირველი შეხვედრებია ცოცხალ
  ხესთან, რომელიც ჩარჩოს არ შეუქმნია.

## უარყოფილი ალტერნატივები

1. **„template/preset“ როგორც ერთეული** — ერთჯერადი ანაბეჭდი; კომპოზიცია შეუძლებელია,
   ხოლო კომპოზიციის გარეშე ეს გენერატორია და არა ჩარჩო.
2. **ერთიანი L7** — აიძულებდა ჩარჩოს დომენურ განაჩენზე ეთქვა სიტყვა, ანუ გადაელახა
   საკუთარი საზღვარი; „ხარისხის ქვითარი“ იმავე ნდობის ხვრელში აღმოჩნდებოდა.
3. **ჩარჩოს აშენება ჰოსტის შიგნით** — ჰოსტში დაბადებული ჩარჩო უნივერსალურს ნაცნობისგან
   ვერ არჩევს: ყველაფერი მუშაობს, ამიტომ არაფერია გაზომილი.
4. **ბლუპრინტის დატოვება `proposals/`-ში** — კანონი 15: მდებარეობა, რომელიც ვერ აცხადებს,
   წესს ავტორიტეტს არ აძლევს, მკითხველი კი ამას ვერ არჩევს. სწორედ ეს იყო დეფექტი.

## ღია ხარვეზები (გამოცხადებული, არა შემოვლილი)

ბლუპრინტის ნაწილი X-ის ექვსი ხარვეზი ძალაშია და ამ ADR-ს არ დაუხურავს:
დოქტრინის თვით-ვერსირებაზე თანხმობის არტეფაქტი · ლეგიტიმურად შეცვლილი `[V]` ფაილის
მდგომარეობა · `foreign` გზის კლასი · ვინ სჯის მსაჯულს · ნაგულისხმევი eval-ნაკრების
არარსებობა · `observe → enforce` ზღვარი, რომელიც რიცხვი უნდა იყოს და არსად გამოცხადებულა.
სანამ ეს უკანასკნელი არ არსებობს, **P9 აღწერაა და არა მექანიზმი.**
