# 16. Documentation as learning -- what a technical document answers
Every technical document answers nine questions: **what** it is · **why** it exists · **where** it sits
(layer, owner, boundary) · its **input, output and lifecycle** · the **technology or standard** it follows ·
the **alternatives and trade-offs** · its **failure modes** and fail-closed path · **how it is tested and
proven** · how it is **versioned, migrated and deprecated**. In that order: foundation -> concept ->
architecture -> mechanism -> example -> failure modes -> implementation -> tests -> evidence -> operations
(Diataxis for the kind of document; docs-as-code for its home).
